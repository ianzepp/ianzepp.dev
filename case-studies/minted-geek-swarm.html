Agent work has to outlast a turn.

A model call is a moment. The work around it needs identity, a durable home, tools, and a way to resume. Minted Geek Swarm is a Rust platform that brings those pieces behind one authenticated gateway, then carries bounded work context into agent rooms with a record of what woke them.

The brief

Work keeps its identity between prompts.

The earlier Monk API study traces one platform idea through Minted.IO, Motivis, and a rebuild from memory. Swarm carries that lineage into a new operating problem: agents must work across pauses, handoffs, and service boundaries while staying inside a tenant's authority.

That makes orchestration a platform concern. A room needs to know who is acting, which work is available, what tools that identity can reach, and what event triggered its next turn. Swarm gives those responsibilities explicit service boundaries: Key for identity, Agent Queue Service (AQS) for durable tasks, LLM rooms for agent execution, SES for mail, VFS for tenant files, and Model Context Protocol (MCP) for tool transport.

The goal is a system that can pause without losing the shape of the work. Tasks and messages stay in durable services. A room receives a bounded view of what matters now and references that point back to the source records.

The request boundary

Identity travels with every request.

The server binary, swarmd, composes the authenticated HTTP gateway. Its auth resolver checks a bearer token and builds a trusted kernel frame with the tenant, actor, authority, capabilities, and optional storage scope. Domain handlers receive that structured context as they process a request.

This keeps tenant ownership in the execution path. Tenant identity comes from trusted token resolution before a model or domain service acts. The same structured identity context reaches downstream handlers, where each domain applies its own record and capability rules.

The room loop

A room gets a short brief and a trail back.

When the role loop wakes, the host reads open AQS items and inbound mail from durable state. It filters tasks for the agent's identity, gathers a small summary of actionable items and unread messages, and adds the agent's role and active goal. The dispatch message carries that bounded summary into the room; full tasks and messages remain in their durable services.

Each dispatch has a durable ledger record linked to the room message. Its packet can include an AQS evidence handle, so a reviewer can identify the task that caused the wake-up. The queue remains the source of the task; the room history records the dispatch that acted on it.

The architectural choice

Keep the source of work durable and the prompt bounded. Agents get enough context to act, while the task or message keeps its own identity outside the prompt.

The operator surface

Lifecycle stays visible to the person running it.

The swarm CLI calls this lifecycle a hive: one tenant's agent workspace, provisioned from an opening brief and removed through a matching down command. An operator can create and dissolve it through the gateway while keeping the lifecycle explicit.

Birth

swarm hive up takes a file, standard input, or a prompt, then creates the tenant-scoped workspace through the normal gateway.

Dissolution

swarm hive down removes one hive and reports the lifecycle result to the operator.

The repository includes managed-local scenarios for tenant isolation and a structural check from an AQS task to a room dispatch. This page does not treat them as current production evidence.

The evidence boundary

The case for Swarm is architectural.

The current source contains a gateway that carries tenant identity, separate service surfaces, durable task and room records, dispatch initiated by sensors, and an operator CLI. The integration source contains managed local scenarios for tenant isolation and lifecycle behavior. The repository is private; these scenarios are the available implementation evidence, with hosted usage and uptime outside their scope.

This study makes no customer adoption, throughput, reliability at scale, or cost savings claim. It stays with the evidence the implementation supports: a platform that gives agent work a tenant, a durable home, bounded context, and a record of how it reached a room.
