The First Protocols

Thesis

The patterns were already here

Twenty-six years before the Radix compiler and the agent fleets, a twenty-year-old Marine wrote two open-source network tools in eight months. The code is not remarkable by 2026 standards. What is remarkable is how much of the later career—the protocol-level thinking, the refactoring discipline across versions, the instinct to design the spec and not just implement it—is already visible in projects that predate the career itself.

This is not retrospective mythology. The code is archived. The file headers carry their own dates. The Nmap project cited KMap by name in its contemporary release notes. The evidence is primary.

The two projects share an eight-month window, a common author, and a single concern: network protocols. One wraps a scanner in a desktop GUI. The other implements a peer-to-peer network from the binary wire format up. Both are complete, shipped, open-source systems—not sketches.

Tool I · Kmap

The network scanner gets a face

Kmap is a KDE desktop frontend for Nmap—the port scanner that was, in 1999, already the standard tool for network reconnaissance. The GUI wraps Nmap's command-line interface in a native Qt application: configuration dialogs for scan types, stealth options, decoy hosts, and timing; a process manager that pipes stdout and stderr to multiple views; scan history with argument persistence.

Two versions survive. Version 0.6.1 (October 1999) has 21 source files and a monolithic option stack. Version 0.7.1 (January 2000) refactors to 17 files, separates the port, info, and nmap output windows into independent dockable views, introduces a centralized KmConfig persistence layer, and starts KDE 2 / Qt 2.1 compatibility work.

The refactoring is the interesting part. Twenty-one files to seventeen is not code golf—it is architectural reorganization. The changelog is specific: "Rewrote frontend and separated the port/info/nmap windows from the main entry widget. They are now full-fledged desktop windows." This is a design decision about modularity, made between versions, by a single author, before the code was three months old.

Voice

The personality is already there. When Nmap cannot be found on the system, Kmap 0.7.1 displays: "I looked all over for Nmap, and I just couldn't find it installed anywhere. I rooted all through bin/ and sbin/ in all the system, local, and home directories, and it just wasn't there!"

Tool II · GnutellaLib

The peer-to-peer protocol, from the wire up

GnutellaLib is a complete implementation of the Gnutella file-sharing protocol in a single Python file. Not a client—a library and daemon that implements the full protocol: binary message parsing, multi-threaded connection management, message routing with TTL enforcement, servent caching, file indexing with recursive directory walks, and a search engine supporting glob, regex, size, and date filters.

The implementation handles both sides of the Gnutella handshake on a single TCP port. An incoming GNUTELLA CONNECT/0.4 is rewritten to a standard HTTP CONNECT and dispatched through the same handler tree. Outgoing connections send the handshake, verify the response, transmit a login ping, and spawn a message loop on a new thread.

Protocol constants · gnutellalib.py
gnutella_ping       = 0x00
gnutella_ping_rpl   = 0x01
gnutella_push       = 0x40
gnutella_query      = 0x80
gnutella_query_rpl  = 0x81

Five message types. Each one is a class with encode(), decode(), and reset() methods, backed by struct.pack and struct.unpack with explicit format strings. The GnutellaHeader alone is <16sBBBi—a 16-byte message ID, three unsigned bytes for function ID, TTL, and hop count, and a signed 32-bit payload length. Every message passes through a five-stage verification pipeline before it reaches the handler:

verify_fid verify_mid verify_ttl verify_hops handle

The message cache uses LRU-style slicing: when the cache exceeds 50,000 entries, the oldest 1,000 are discarded. Servent addresses are cached separately with the same pattern. Broadcasts exclude the originating link. Replies are routed back along the path of the original message.

Beyond implementation

The file does not stop at implementing the Gnutella spec. It proposes a redesigned protocol header: drops the hops field (redundant with TTL), adds a version byte for per-message compatibility, and aligns the header to 24 bytes. It designs an extended query record format with ten search types (0x00–0x0b)—glob, regex, file size, creation date, modification date, content matching. This is protocol design, not just protocol implementation.

Continuity

The threads that run forward

These projects are twenty-six years old. They are interesting because the patterns they contain did not stop. Every thread below connects 1999 code to 2025–2026 code—not by descent (no line of Kmap or GnutellaLib survives in any current project) but by disposition.

Protocol thinking

1999: Implements and redesigns binary wire protocols. Proposes header improvements the spec committee hadn't considered.
→ 2025: Designs a programming language grammar, a compiler IR pipeline, agent message schemas, and mail-based coordination protocols.

Refactoring across versions

1999: Kmap 0.6.1 → 0.7.1. Twenty-one files to seventeen. Monolith to dockable views. Three months between versions.
→ 2025: Minted.IO → Motivis → Monk API. Same platform vision rebuilt clean-room three times across a decade.

Complete single-author systems

2000: A 2,313-line Python file that implements an entire P2P network—daemon, protocol, search engine, CLI, file server.
→ 2026: A 281K-line Rust compiler. A multi-agent runtime. The scale changed; the scope discipline didn't.

Open source from day one

1999: GPL v2 on both projects. Published to public archives. Archived on Google Code. Nmap release notes cite the work.
→ 2025: GitHub profile with 40+ public repositories. Every case study links inspectable source.
The deeper pattern

In 1999 the author wraps a network scanner in a GUI. In 2025 the author wraps agent fleets in orchestration layers. The architectural instinct is the same: take a powerful but raw protocol-level tool and build the infrastructure that makes it usable at scale. Kmap makes Nmap accessible. Vivarium makes agent coordination accessible. The abstraction level moved up; the impulse didn't.

Coda

What survived and what didn't

No line of Kmap or GnutellaLib code runs in any current project. The KDE 1.x widget toolkit is extinct. Python 1.5's whrandom module was removed from the standard library fifteen years ago. The Gnutella network itself is a historical footnote—replaced first by BitTorrent, then by streaming, then by irrelevance.

What survived is disposition. The instinct to think at the protocol level. The discipline to refactor between versions rather than just shipping the first thing that works. The habit of publishing source and building in the open. The tendency to go beyond implementation into design—to not just use a spec, but to propose a better one.

Those tendencies are visible in the Radix compiler, in the Monk API iterations, in the Faber grammar, in the agent fleet infrastructure. They did not start in 2025. They started in a barracks, on a machine running KDE, in a file that opens with begin: Thu Oct 28 14:00:30 EST 1999.

The code is gone. The instinct is load-bearing.
