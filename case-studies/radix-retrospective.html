Seven months from first commit to release candidate.

How a programming language compiler went from a TypeScript prototype to a modularized Rust system with GPU codegen, autograd, and multi-locale diagnostics — and the five pivots that shaped the path.

The Radix compiler didn't follow a roadmap. It followed a process: write the goal, bound the work, implement a coherent slice, audit the result separately. The roadmap emerged from that loop — and the pivots emerged from the audits.

What makes this retrospective worth reading isn't the output volume. It's the pattern of deliberate course-correction: five times the project changed direction significantly, and each time the pivot was a response to evidence, not a failure of planning.

Dec 22 – Dec 30, 2025 v0.3.0 – v0.6.0

The multi-target prototype

Faber launched as a TypeScript compiler targeting everything at once: TypeScript, Python, Zig, Rust, C++, and WASM backends, all in the first week. Editor tooling (Prettier, tree-sitter, Zed extension) shipped alongside. The Latin keyword syntax, Unicode operators, and genus/pactum/ordo type system were established immediately.

313 commits in v0.6.0 alone. This was the "prove the concept exists" phase — breadth over depth, shipped fast to see what the language felt like in practice.

Dec 30 – Jan 5, 2026 v0.7.0 – v0.14.0

The self-hosting attempt

An aggressive push to make Faber compile itself. The bootstrap compiler (Rivus) was written in Faber, a semantic analyzer and TypeScript codegen were ported, and 25 .fab source files formed the self-hosted core.

Pivot 1 — Bootstrap target

v0.9.0 (Dec 31): The bootstrap target changed from Zig to TypeScript. Zig was architecturally cleaner but TypeScript was pragmatically faster for self-hosting velocity. The decision prioritized learning speed over target elegance — a pattern that would repeat.

Latin morphology was introduced in v0.14.0, beginning the long arc of linguistic precision that would define the project.

Jan 6 – Jan 13 v0.15.0 – v0.22.0

Stdlib and language research

The annotation-driven stdlib framework (Norma), HTTP/database/serialization libraries, and the LLM learnability trial harness (Probationes) all arrived in this week. Codegen backends for Rust, C++, and Zig were rebuilt — and then almost immediately archived.

Pivot 2 — Target narrowing

v0.22.0 (Jan 12–13): Faber was narrowed from six codegen targets to TypeScript-only, with Go added as the second priority. Rust, Zig, and C++ backends were archived as broken. The decision: stop spreading thin across six half-working backends and focus the reference compiler on one that works completely.

Pattern

This is the first instance of what becomes a defining discipline: when something isn't earning its complexity, cut it. The project would prune features, syntax, and entire subsystems dozens of times over the next six months.

Jan 13 – Jan 26 v0.23.0 – v0.29.0

CLI, microcompilers, and language pruning

The CLI framework was built, rebuilt, and refined. The Nanus microcompiler experiment produced tiny standalone compilers in Rust, Go, and Python — probing whether Faber could be implemented at minimal scale. Faber Glyph format arrived, replacing ASCII compound operators with Unicode.

Language pruning accelerated: fit/fiet disabled, consilia/ directory removed, bindings unified under fixum/varia. Each release was smaller and more focused than the last — the project was converging.

Jan 26 – May 20 v0.30.0 – v0.33.0

The Rust rewrite

Pivot 3 — Compiler rewrite in Rust

v0.30.0 (Jan 26–29): The entire compiler was rewritten in Rust. The TypeScript compiler ecosystem (Faber, Rivus, Nanus) was superseded by radix-rs: ~8,800 lines with full HIR lowering, bidirectional type inference, six-pass semantic architecture, and borrow analysis. This was the foundational architectural shift of the project.

The gap between v0.30.0 (Jan 29) and v0.31.0 (Feb 15) — and then between v0.31.0 and v0.32.0 (Apr 3) — reflects the Gauntlet AI fellowship absorbing primary attention. The old TS compilers were pruned, the workspace consolidated, and the CLI rebuilt from scratch.

v0.33.0 (May 20) was the first real compiled release: a faber binary, CI release pipeline, Docker artifacts. Everything before this was retrospective tagging.

The quiet months

February through April had only 3 releases total. Attention had shifted to the Gauntlet AI fellowship — commit frequency stayed high, but on fellowship projects, not Faber. The rewrite continued in the margins. When the fellowship ended and focus returned, the architectural groundwork was ready to accelerate.

May 21 – Jun 22 v0.34.0 – v0.40.0

MIR, tool separation, and maturation

The compiler split into two tools: faber (user-facing CLI) and radix (compiler). The Glyph clean break removed the last ASCII compound operators.

Pivot 4 — MIR foundation

v0.36.0 (May 22–23): A proper Middle Intermediate Representation was established with 10 lowering phases. This is the architectural layer that enabled every subsequent backend — LLVM, WASM, Metal, WGSL — to consume the same representation. Without MIR, multi-target codegen was ad-hoc per-backend translation. With MIR, it became systematic.

v0.40.0 was a turning point in project methodology: 382 commits organized into an 8-stage polish campaign with the CISTA package manager. This is where the campaign/factory pattern became the dominant organizational structure.

Jun 22 – Jun 28 v0.41.0 – v0.59.0

Scripting runtime and type system expansion

Nineteen releases in six days. The compiler gained a scripting interpreter (Scena, v0.50.0), tensor types (v0.52.0), sized numeric primitives, and indexed tensor types with angle-bracket generics (v0.59.0). The literal system was overhauled: guillemet strings, template strings, byte literals, JSON valor literals.

The pace here reflects the MIR foundation paying off: each new type or feature drops into the existing lowering pipeline rather than requiring per-backend implementation.

Acceleration

The project went from 4 releases in December to 19 releases in a single week in late June. This isn't just faster typing — it's the compound effect of architectural decisions (MIR, campaign methodology, clean breaks) reducing the cost of each incremental change.

Jun 28 – Jul 9 v0.60.0 – v0.70.0

GPU codegen and target promotion

Pivot 5 — GPU and multi-target promotion

v0.66.0–v0.70.0 (Jul 1–9): The compiler became a real multi-target system. GPU kernel emission for WGSL, Metal, and LLVM. TLA+ verification infrastructure. All 5 MIR emit targets promoted from probe to supported. v0.66.0 alone spanned 818 commits. This was the moment the compiler stopped being a single-target tool and became a platform.

Reader-locale diagnostics arrived (v0.68.0) — the compiler rendering errors in Thai, Vietnamese, Chinese, Hindi, Arabic, and Latin. The code-first diagnostic identity system made this tractable: stable codes, not human-readable messages, are the primary identifier.

The workspace was aggressively reorganized: ~39,000 lines extracted to sibling repositories. The compiler shed weight as it gained capability.

Jul 9 – Jul 22 v0.71.0 – v0.77.0 + RC1

Modularization and 1.0 preparation

The compiler was modularized into separate crates in an 8-stage extraction (v0.76.0): radix-diagnostics, radix-lexer, radix-syntax, radix-types, radix-hir, radix-mir, codegen crates per target, runtime-contract, stepper, coverage. Crate manifests were realigned — v0.76.0 was the first release where the tag version equals the manifest version.

v0.77.0 brought graphics pipeline reflection end-to-end, an autograd/backward differentiation pipeline, and WGSL workgroup reductions. The compiler can now emit GPU compute kernels with gradient support.

The 1.0 release campaign was scaffolded (319-line campaign document) and an RC1 source-tag candidate was cut, awaiting operator approval.

Recurring patterns.

Relentless pruning

Features, syntax, and subsystems are regularly removed. The project consistently sheds complexity rather than accumulating it.

Campaign methodology

From v0.40.0 onward, all work is organized into formal campaigns with goals, stages, delivery documents, and closeout ledgers.

Architecture before velocity

Each major pivot slowed visible output temporarily but unlocked compounding returns. The Feb–Apr valley preceded the Jun–Jul acceleration.

Clean breaks over deprecation

When old syntax or systems are superseded, they're removed, not deprecated. No backwards-compatibility shims. The codebase stays in one present tense.

Latin morphological convergence

Every release refines the Latin naming. Keywords, types, stdlib methods, diagnostics — all converge on morphologically correct Latin.

Workspace extraction arc

The monolith progressively extracts subsystems to sibling repos and modularizes internally. The compiler gets smaller as it gets more capable.

The trajectory from a TypeScript prototype to a modularized Rust compiler with GPU codegen isn't a story about speed. It's a story about a process that produces good pivots: write the goal, do the work, audit the result, and change direction when the evidence says to.

The five pivots — bootstrap target, target narrowing, Rust rewrite, MIR foundation, GPU promotion — were not failures of the original plan. They were the plan working correctly. Each one emerged from an audit that said: what we built works, but it won't scale to what we need next.

The 1.0 RC exists because seventy-five prior releases earned it.

The roadmap emerged from the process. The pivots emerged from the audits.
