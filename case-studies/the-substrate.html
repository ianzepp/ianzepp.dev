The substrate. Evidence and coordination.

Cassio and Vivarium are the infrastructure you build around agents to make them sustainable over months, not minutes. Cassio is the evidence layer — 13,512 AI session transcripts normalized, compacted, and made searchable. Vivarium is the coordination layer — 61 agent roles exchanging 20,672 messages across mailspaces that decide what work is ready and who does it. Two tools, one operating surface.

The thesis

Agents need infrastructure, not just prompts.

The visible output of AI-assisted engineering is code. But code is the product of sessions, and sessions produce transcripts, and transcripts accumulate into a corpus that no human can read at scale. Meanwhile, agents that coordinate — dispatching work, reporting results, auditing output — need a communication surface that persists across sessions, supports role-based routing, and tracks what happened. Without infrastructure for evidence and coordination, agent fleets are just expensive typing.

Cassio and Vivarium solve the two halves of this problem. Cassio turns raw session logs from 10 different AI coding tools into a normalized AST, then compacts them through an LLM pipeline into daily, weekly, and monthly intelligence. Vivarium treats email as a durable agent data surface — local mailspaces with typed roles, work graphs, and a readiness frontier that decides which work is eligible for dispatch.

Together they form the substrate the Mind/Head/Hand fleet architecture runs on. The loop is closed: agents produce sessions, Cassio compacts them into evidence, Vivi's mailspaces route the evidence to the right roles, and those roles dispatch the next round of work.

Cassio · the evidence layer

Ten formats, one AST.

AI coding tools each produce their own session log format — Claude Code writes JSONL, Codex writes JSON rollouts, Hermes stores SQLite, OpenCode writes JSON, and each has its own schema, its own quirks, its own definition of what a "message" is. Cassio normalizes all of them into a shared AST: Session → Message → ContentBlock → Tool. Adding a new tool requires one parser module. Everything downstream — formatting, compaction, search, cost estimation, training export — only knows the AST.

Claude Code Codex OpenCode Hermes Claude Chat Claude Desktop pi Kimi Code Grok Cursor

The pipeline follows the compiler pattern deliberately: input formats are the source language, the AST is the intermediate representation, and formatters are the backends. This is why 10 parsers were added in 5 months without touching the output layer.

Self-referential

Cassio processes the transcripts of the AI sessions that built Cassio. The tool that generates evidence was itself built by the process it documents. The 13,512-file corpus includes Cassio's own development history.

The compaction pipeline is the distinctive feature. Raw sessions compact into daily summaries via a local LLM (ollama or llama.cpp). Dailies compact into weeklies. Weeklies compact into monthly personality and pattern analyses via cloud models (Claude or Codex). Each tier chunks automatically when content exceeds the context budget. Checkpoints persist for resume-on-failure. The result is navigable intelligence at every timescale.

Vivarium · the coordination layer

Email as agent infrastructure.

Vivarium — named after Cassiodorus's 6th-century monastery for preserving written works — treats email as a durable data surface for AI agents. Not email the UI. Email the protocol: messages with senders, recipients, threads, and persistence. Local mailspaces give each project a self-contained coordination surface with typed roles (inbox, sent, done, archive, tasks, memos, wants, needs), work graphs imported from Mermaid flowcharts, and event-driven watch surfaces.

The public binary is vivi. A companion binary vivi-pty provides a project-scoped PTY runtime for managing Fleet agent processes via Unix sockets. Three mail provider paths coexist: standard IMAP/SMTP, Proton Bridge, and a direct Proton Mail API integration that bypasses the Bridge entirely — including SRP authentication and OpenPGP encryption/decryption.

Authority split

Vivi decides what work is ready (topology, readiness frontier, role capacity). Mind decides who does it (dispatch). Fleet executes (process management). Three systems, three responsibilities. Vivi never spawns an agent. Mind never computes readiness. The boundaries are load-bearing.

The role topology

Mind is the hub. Everything routes through it.

The Faberlang mailspace runs 37 distinct agent identities organized in the Mind/Head/Hand hierarchy. Mind is the dispatch nexus — the highest-traffic node in every message flow. Heads (CTO, CEO, CPO, CSO, CXO, CMO) own domain judgment. Hands execute. Specialists (hunters, auditors, planners, reviewer, strategist, purity, correctness) handle specific cross-cutting concerns.

Work graphs

Mermaid in. Ready frontier out.

Vivarium imports work graphs from Mermaid flowcharts — the same format you'd use to document a process diagram. But these aren't documentation. They're executable: each node is a work item with a state (open, active, done). Edges encode dependencies. The ready frontier is the set of nodes whose dependencies are all done — the work that is eligible right now.

The Faberlang workspace has two live graphs: rivus-campaign and rivus-v2, with 48 nodes, 45 edges, and 20 active attempts. Nodes follow a phased pattern — P0 Bootstrap, P1 Spine, P2 Semantic — with each phase containing Admit, Goal-Audit, Forge, Check, Delivery, and Delivery-Audit steps. This is the factory pattern expressed as a graph: the phases are the pipeline, and the readiness frontier is the scheduling discipline.

Vivi decides readiness, not dispatch

Vivi computes which nodes are ready. It does not decide which agent works on them. That's Mind's job. The authority split means the work-graph engine never needs to understand agent capabilities, and the dispatcher never needs to understand dependency topology. Each system does one thing well.

Shared DNA

The same engineering discipline, twice.

Cassio and Vivarium share more than a use case. They share an engineering culture:

Hygiene ratchets. Both projects enforce code quality via compile-time test suites that scan production source. Cassio caps .unwrap() at 11 calls and bans panic!(), todo!(), and inline test modules. Vivarium sets per-file line limits (1,000), per-function limits (60 lines), total LOC budgets, and the same inline-test ban. The budgets can only decrease — a ratchet that tightens as the code matures.

Companion test files. Both projects ban #[cfg(test)] modules inside production files. Every module gets its own *_test.rs companion file. This isn't convention — it's enforced by a test that fails the build if violated. The separation means production files contain zero test infrastructure.

Burst development. Cassio: 112 commits across 18 active days (6.2 per active day). Vivarium: 312 commits across 24 active days (13 per active day). Long pauses between bursts. Both projects were built in concentrated, deep sessions — not spread-out daily commits.

Parser-AST architecture. Cassio normalizes 10 AI tool formats into a shared Session AST. Vivarium normalizes IMAP, Proton Bridge, and direct Proton API into a shared message store. Different domains, same structural pattern: heterogeneous inputs normalized through a trait-based parser layer into a unified representation that downstream systems consume without knowing the source.

The closed loop

The infrastructure feeds itself.

The loop is literal, not metaphorical. Agents produce coding sessions. Cassio discovers those sessions automatically (it knows where every supported tool stores its logs), normalizes them into AST, formats them as Markdown transcripts, and compacts them into daily intelligence. That intelligence enters Vivi's mailspaces. Mind reads the evidence. Mind dispatches work to Hands via the mailspace. Hands produce sessions. Cassio processes them.

The 13,512-file corpus and the 26,530 coordination events aren't parallel facts. They're the same loop at two measurement points — one upstream (what happened), one downstream (what to do next). The infrastructure is the loop.

The substrate doesn't do the work. It makes the work legible — to the human who audits it and to the agents who continue it.
Patterns

What the substrate reveals.

Evidence is infrastructure

13,512 transcripts are useless without compaction. Cassio turns volume into intelligence: session → daily → weekly → monthly. Each tier is a different question answered at a different timescale.

Email is underrated

Email has senders, recipients, threads, persistence, and search. Agents need all five. Vivi didn't invent a new protocol — it used the one that already works and added readiness computation.

Ratchets over rules

Both projects enforce quality with monotonically-tightening budgets. The unwrap count can go down, never up. The max function length can shrink, never grow. Discipline that compounds.

Authority boundaries

Vivi computes readiness. Mind dispatches. Fleet executes. Three systems, three jobs. No system does another's work. The boundaries survived because they were drawn before the code was written.

Parser-AST everywhere

Cassio: 10 input formats → one AST. Vivarium: 3 mail providers → one message store. The same structural pattern in both tools, because the same problem (heterogeneous inputs, uniform downstream) appears in both domains.

Build the loop, not the tool

Neither Cassio nor Vivarium does the actual engineering. They make the engineering process observable and coordinable. The value is in the loop they form together, not in either tool alone.

The substrate is the least visible part of the system and the part that makes everything else possible. Without Cassio, 13,512 session transcripts are a write-only archive — evidence that exists but can't be used. Without Vivarium, 61 agent roles have no coordination surface — they produce work but can't route it, track it, or decide what's ready. Together they close the loop: evidence feeds coordination, coordination produces sessions, sessions become evidence.

This is the infrastructure you build when you're serious about running agents over months, not minutes. It's not glamorous. It doesn't have a demo. What it has is 26,530 coordination events across two live workspaces, a 5 GB transcript corpus compacted into navigable intelligence, and a readiness frontier that runs in production today. The substrate does its job by being invisible.

The infrastructure does its job by being invisible. The evidence is that the loop keeps running.
